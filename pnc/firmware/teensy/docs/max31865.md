# PT1000 / MAX31865 commissioning

This change adds measurement and reporting. It does not select the PT1000 as
PHOTONS' normalization authority or modify the existing BME280 calibration.

## Installed wiring

| MAX31865 | Teensy terminal | Kynar color |
| --- | --- | --- |
| VIN | 3.3V (not Teensy VIN) | Purple |
| GND | GND | Black |
| CLK | 27 | Yellow |
| SDO | 39 | Blue |
| SDI | 26 | Green |
| CS | 38 | Orange |
| 3V3, RDY | Disconnected | — |

The probe sits beside the fiber beneath the heating pad. The board must be the
PT1000 variant with a 4300-ohm reference resistor. The firmware assumes a
1000-ohm-at-0-C platinum RTD with the IEC 60751 coefficient set.
The board's three-wire jumpers must also be configured; software cannot replace
those physical connections.

## Initialization and acquisition

At boot, `max31865_init()` holds CS high, selects SPI1 MOSI 26, MISO 39 and SCK 27,
and then calls `SPI1.begin()`. Selecting MISO before beginning is essential:
Teensy's default MISO1 is pin 1, already used by GNSS PPS. The standard SPI bus
would use clock pin 13, already occupied by OCXO1.

Each transaction uses 500 kHz, most-significant bit first, SPI mode 1. CS goes low
for a register transaction and high afterward. SPI has no I2C-style device
address or ACK. Configuration/threshold readback detects common absent-device
or communication failures; it is not a device-identity check or data CRC.

Once per second the foreground service:

1. Reasserts fault thresholds, selects three-wire mode and 60 Hz rejection,
   clears latched faults, and turns on the measurement bias.
2. Returns to normal work for at least 10 ms of bias settling.
3. Starts one conversion, then returns to normal work for at least 65 ms.
4. Reads configuration, resistance code, thresholds and fault bits; turns bias
   off; converts resistance to temperature using integer-backed `Double`.

Conversion uses the Callendar-Van Dusen relation, including the subzero term,
within -200..850 C. The software range is not a rating for the probe assembly.
Four printed decimal places retain computation detail; they are not a claim of
0.0001 C resolution or accuracy. Bias is off between conversions to reduce
self-heating. No ADC wait loop, delay(), sensor ISR, or native floating-point
math is introduced. SPI byte transfers themselves are synchronous, short
foreground operations. Acquisition uses TimePop's existing foreground-service
registry; timing interrupts remain able to preempt it.

## Reports and data flow

After deploying the Python files, rebuild/flash the Teensy with the existing
workflow and restart the Pi SYSTEM process so it loads the new RTD monitor.
No separate Adafruit library installation is needed: the Teensy package already
provides SPI, and the register driver is included in this patch.

Inspect the compact sensor report first:

```sh
tc system rtd_report
```

The same object is available under `rtd` in:

```sh
tc system report
pc system report
pc system report_metrics
```

Teensy reports only cached acquisition data. The Pi requests the compact
`TEENSY.SYSTEM.RTD_REPORT` once per second in a dedicated background thread.
Pi REPORT reads that cache without doing an SPI operation or synchronous RPC.
This avoids the existing 30-second platform poll interval for the new sensor.
The ordinary slow SYSTEM_STATUS event also includes the cached RTD snapshot.
PHOTONS' existing Pi SYSTEM snapshots therefore carry `rtd` into campaign data.
The metrics command includes the data; this change does not add a title-bar label.

On a healthy reading, expect `status: OK`, advancing `sample_sequence`,
`fault_status: 0`, `temperature_c`, `resistance_ohms`, `raw_code`, and `age_ms`.
A PT1000 near 32 C should read about 1124.474 ohms. `sampled_at_ms32` is Teensy
uptime at result readout, not UTC or an exact sample-aperture timestamp.
Pi `age_ms` conservatively includes RPC transit and cache residence.

| Status | Meaning |
| --- | --- |
| INITIALIZING | No completed observation yet |
| OK | Fresh, successful measurement |
| SPI_ERROR | Configuration/threshold readback failed, or conversion bit stayed set |
| RTD_FAULT | Converter reported a fault; inspect `fault_status` |
| OUT_OF_RANGE | Resistance lies outside the CVD conversion range |
| STALE | Last successful sample is over three seconds old |
| UNAVAILABLE | Pi could not obtain a usable Teensy response |

Fault, stale and unavailable snapshots omit temperature rather than reusing an
old number. The driver retries on the next cycle, including recovery from a
sensor-only power reset. `attempts` and `errors` count acquisition attempts and
failures; `sample_sequence` advances only on successful samples. These counters
reset with Teensy. This adds no new campaign readiness gate.

## Validation

The implementation was checked with an offline mock-SPI host harness executing
the actual driver and project Double implementation: pin selection order,
configuration writes, conversion waits, RTD faults, disconnected SPI, recovery,
out-of-range resistance, stuck conversion, millisecond wrap and delayed service.
A CVD-generated sweep from -199 through 849 C agreed within ADC quantization.
The host checks cannot establish target timing or electrical signal integrity.

Pi cache tests are included:

```sh
python3 -m unittest discover -s tests -p test_system_rtd.py
```

A complete Teensy target build and physical readings must be checked on the Pi.
